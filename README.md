# crustify-libgit2

Safe Rust wrappers over libgit2's public C API; the raw bindings live in the
`libgit2-sys` crate.

## How it was made

The code was generated by [Crustify](https://github.com/crustify-rs/crustify), a
specification-driven AI assistant developed at UC Berkeley to automate C-to-Rust tasks,
and thoroughly reviewed by its own specialized agents.

- Models: primarily Claude Opus 5.5. Claude Fable 5.1 ran some reviews, and GPT-6.1-sol
  and GPT-6-astra some of the wrapping.
- [wavefront](https://github.com/crustify-rs/wavefront): CodeQL-based analysis of the C,
  which plans the work in dependency order.
- [ffibox](https://github.com/crustify-rs/ffibox): ownership and borrowed-handle types for
  the wrappers.
- [ffimap](https://github.com/crustify-rs/ffimap): counts the unsafe code and raw pointers
  on the public API.
- bindgen for the raw bindings; ASan/UBSan, TSan, Miri and BorrowSanitizer to check for
  undefined behaviour.
- [glibc-bindings](https://github.com/crustify-rs/glibc-bindings),
  [openssl-bindings](https://github.com/crustify-rs/openssl-bindings),
  [pcre2-bindings](https://github.com/crustify-rs/pcre2-bindings) and
  [zlib-bindings](https://github.com/crustify-rs/zlib-bindings) for the libraries libgit2
  links; each is built per sanitizer variant, and wraps what libgit2's API uses as the
  campaign reaches it.
