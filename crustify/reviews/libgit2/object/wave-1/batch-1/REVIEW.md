# Review: libgit2 / object / wave 1 / batch 1 (the wave's symbols and callbacks)

Reviewed commit `38e6d1b3e` (review-wave base), covering the 55 `symbol` / `callback`
items the wave's symbol batches landed: batch 5 (`846e7d391`: blob writers, commit
signing, the parent and signature callbacks, mailmap lookups, message prettify, object
id/owner), batch 6 (`af4027d3c`: object types, short ids, tag routines, tree entry
getters) and batch 7 (`84c213038`: tree builder routines, the filter and walk
callbacks), in `object/{blob,commit,mailmap,message,object,tag,tree}.rs` and
`object/sys/commit.rs`. Every item carries its one `Wraps:` anchor. The lifecycle
routines among them (`git_object_{dup,free}`, `git_tree_entry_{dup,free}`,
`git_treebuilder_free`, `git_mailmap_{new,free}`) are the policies the type runs
emitted (`ObjectFree`, `TreeEntryFree`, `TreeBuilderFree`, `MailmapFree`), and
`git_object_{lookup,lookup_prefix,lookup_bypath,peel}` / `git_mailmap_from_*` the
constructors the wave-0 runs and review anchored; they were re-read, not re-emitted.

Object's last wave is wave 3 (`schedule.json`), so this review ran BSan only on its
own reproducer, alone.

| step | outcome |
|---|---|
| lifecycle discovery | not applicable: a symbol-route batch. The lifecycle routines scheduled as symbols are bound to the policies above, which call them, and their `CDrop` / `CRefClone` / `CDupClone` contracts were re-read against the C (`git_object_free` and `git_tree_entry_free` / `git_treebuilder_free` / `git_mailmap_free` skip NULL, `git_object_dup` only counts). |
| wavefront findings | 1 report, resubmitted: `wavefront/treebuilder-insert-id-lookup-type-unchecked` — `git_treebuilder_insert`'s `id` record said the id is looked up in the ODB, but not that the lookup takes the id's type unchecked against the builder's repository (the root of the UB below); the note now states the overflow and the obligation. Spot-checked records hold: `git_blob_create_from_stream` (constructor; the repository kept uncounted), `git_blob_create_from_stream_commit` (dropper of the stream on every path), `git_mailmap_resolve` (results borrow the mailmap and the inputs), `git_object_owner` (`obj->repo`, uncounted), `git_commit_extract_signature`. |
| safe boundary | clean. No public `unsafe fn` and no public raw pointer in the workset; `crustify scan-unsafe --sites` finds in the eight files only the five `extern "C"` trampolines' `&mut *payload` derefs (`raw_ptr_derefs_outside_impl`: `commit.rs` signing, `sys/commit.rs` parents, `tag.rs` foreach, `tree.rs` walk and filter), each documented, and no `*_smell` site. Raw values that stay on the surface are scalars (`type_is_valid(ffi::git_object_t)`, `TreeEntryRef::filemode_raw`). The workset adds no public unsafe API, so there is no `ub_unsafe` suite to review. |
| UB | 1 true positive, fixed: `ub_safe/tree-builder-insert-formats-foreign-id-out-of-bounds` — `TreeBuilderMut::insert` / `insert_entry` handed libgit2 an id of another type than the builder's repository, which `check_entry`'s object lookup formats into a loose path sized for the repository's type: a SHA-256 id in a SHA-1 repository is an ASan heap-buffer-overflow in `git_oid_pathfmt` (the converse reads uninitialised bytes). The wrapper now refuses such an id with `id_fits` whenever libgit2 would look it up, reading the builder's repository through the new crate-private `TreeBuilderRef::repository` (libgit2 has no accessor). Reproducer (`#![forbid(unsafe_code)]`) aborts on the base and exits 0 on the fix, also clean when run alone under BSan; regression `tests/ub_safe/tree.rs::routines::ids_of_another_type_are_refused_before_the_lookup`, which aborts under ASan with the check removed. Otherwise no candidate survived: an ASan probe through the public API over odd paths for the four blob writers (`""`, `.`, `..`, symlinks, dangling links, 5000-byte names, a 5 MiB stream dropped uncommitted, a 3 MiB one committed through filters), `create_with_signature` / `extract_signature` over parsable and unparsable contents, empty, newline and 3000-byte fields, tag buffers (leading slashes, empty and 2000-byte names, wrong and missing targets, uppercase ids, bad taggers), lightweight names, list patterns, deletes, every `core.abbrev` value for `short_id`, `from_name`, `prettify` with high comment bytes, mailmap entries with empty strings, and tree builder names, modes and writes, ran clean (LSan included). Every workset routine taking an id was checked for the same unchecked lookup: the others refuse foreign ids already (`extract_signature`, `TreeEntryRef::to_object`, the lookups) or parse ids with the repository's type (`create_with_signature`, `tag::create_from_buffer`). |
| equivalence | no defect. The existing suites compare every routine with C after each step (blob writers over filters and symlinks, signing and extraction, tag creation/list/delete, short ids, entry getters, builder scripts with allocation-failure sweeps). Gaps filled in `tests/equiv/commit.rs::signatures::signatures_match_c`: signed contents that parse but have no blank line (libgit2's `append_header` refusal, never reached before: the existing case did not parse), and the field `"\n"`, which libgit2 matches against the blank line before the message and reports as a malformed header when the message's first line starts with a space and never ends. New documented divergence (`tests/equiv/tree.rs`, `insert` docs): the foreign-id refusal above, made before libgit2's name check and also when strict object creation is off. |
| internal | 1 defect, fixed: `internal/parent-walk-writes-the-commit-after-a-refusal` — `ParentCallback::walk_with` (the seam for the future `git_commit_create_from_callback` wrapper) stopped a refused or panicking walk by handing libgit2 the zero id, relying on strict object creation to fail it; with that option off libgit2 wrote the commit with a zero parent and created the unborn reference to update, while `walk_with` reported failure. It now collects every parent before libgit2 runs, so a refusal or a panic never lets it write. Regressions `failed_walks_write_nothing_without_strict_creation` (fails on the base) and `walks_collect_every_parent_first` (Miri). |
| conventions | none to fix: `// SAFETY:` on every block, `addr_of!` projections, Rust naming with prefixes dropped, `Wraps:` / `Handwritten` anchors; `rustfmt +stable --edition 2024` on every touched file but `tests/ub_safe/commit.rs` (not rustfmt-clean at the base; one doc comment edited by hand), `cargo clippy --workspace --all-targets` clean. |
| misc | 1 defect, fixed: `misc/create-ext-options-docs-name-the-removed-raw-seam` — `CreateExtOptions`' docs justified `!Send`/`!Sync` by the raw `set_sign_callback` seam batch 5 replaced with `set_signer`, and `tests/ub_safe/commit.rs` still listed that seam among its compile-fail checks; both now describe the signer borrow. Noted, not changed: under the nightly sanitizer toolchains, `tests/ub_safe/compile_fail/commit_array_outlives_repository.rs` (a `git_commitarray` case outside this workset) mismatches its expected stderr, as the campaign records for trybuild cases on those toolchains; the ASan/TSan runs below skip `compile_fail`, which passes on stable. The `SignatureCallback` trampoline forms `&mut SignatureCallback` from its payload for the whole closure call, so a future `git_commit_create_ext` wrapper must not let the closure reach options lent the same signer (no public path calls C with options today). |
| coverage | Rust (`cargo llvm-cov`, `coverage` variant, whole crate): the eight files have no uncovered production line but the `!runtime_pinned()` early returns of constructors taking a handle (unreachable), the `unreachable!("git_*_dup cannot fail")` arms, the `ParentCallback` trampoline's guard against a second call after an unresumed panic (unreachable: `call` resumes at once, and walks use the collected trampoline), the `#[ignore]`d 2 GiB `data_is_binary` test, child-failure message formatting, and test closures that must not run. C (gcov of the `coverage` build, private `GCOV_PREFIX`): 100 % of lines for the blob writers' entry points and `git_blob__create_from_paths`, `git_message_prettify`, every `git_object_*` item, `git_mailmap_{new,add_entry,from_*,resolve}`, `git_tag_{create_lightweight,delete,list,list_match}`, every tree entry getter and builder routine (`check_entry` included); the added equivalence cases cover `git_commit_create_with_signature`'s `append_header` refusal and `git_commit__extract_signature`'s first-line `malformed` arm. Remaining uncovered: OOM arms (`append_header`, `git_commit__extract_signature`, `git_treebuilder__write_with_buffer`), races between `lstat` and the read (`write_file_stream`'s short read and open failure, `write_symlink`'s length mismatch), failing odb streams/writes and filebuf flushes (environment-dependent; running as root defeats permission tricks), `git_tag_create_from_buffer`'s odb-load failure (the wrapper answers it before C), `git_commit_create_with_signature`'s odb-load failure (reachable only with strict creation off on a pathless repository), and the NULL arms of `git_mailmap_free` / `git_treebuilder_free` / `git_mailmap_entry_lookup`. |
