# Review: libgit2 / util / wave 0 / batch 2 (`git_error_clear`, `git_error_set`, `git_error_set_oom`, `git_error_set_str`)

Reviewed commit `ad5e40d35` (safe setters `clear`, `set`, `set_without_message`,
`set_str`, `set_oom` and the shared `runtime_pinned` seam in
`crustify/rust/libgit2/libgit2/util/sys/errors.rs`), on the wave branch after
util wave 1 batch 0 (`last`) and review batch 1 (`ErrorClass` fixes).

| step | outcome |
|---|---|
| lifecycle discovery | not applicable: four free functions, no `type` or `raw-lifetime` item. |
| wavefront findings | correct and complete: `fmt` / `string` borrowed for the call only, NULL accepted by `git_error_set` and rejected by `git_error_set_str`, the sticky out-of-memory buffer, the `errno` consumption for `GIT_ERROR_OS`, and the pre-init TLS hazard all re-verified against `errors.c` and `str.c`. No report. |
| safe boundary | no `unsafe` or raw pointer in the public surface. The class argument was the raw `ffi::git_error_t` (`u32`) with a note that the safe wrapper "replaces it"; `ErrorClass` landed in the same wave and was never joined up, so any `u32` reached libgit2 as a class and consumers wrote `ErrorClass::Odb.into()` — 1 report: `unsafe/setters-take-raw-git-error-t` (setters now take `ErrorClass`; a raw constant fails to compile). Every `// SAFETY:` comment is specific and was re-checked against the C bodies. `crustify scan-unsafe` for the four names: no raw-pointer, deref or slice sites, no undocumented unsafe. |
| UB | no candidate survived. Reviewed by hand: the `"%s"` format with any `&CStr` (directives literal, no argument read), the NULL format path (`fmt` checked before any `va_arg`), message copies of every size through `git_str`'s growth and its overflow / failed-realloc paths (buffer marked `git_str__oom`, `git_str_dispose` skips it), thread-state allocation failure, thread exit and TLS-destructor ordering (Rust TLS destructors run before libgit2's key destructor), the `errno` save/restore around the first pin, and a failed `git_libgit2_init` (nothing reaches `errors.c` afterwards). Added `ub_safe` coverage for errors set from a thread-local destructor during thread exit (ASan/LSan). Plain, ASan/UBSan (with LSan), TSan, BSan and Miri runs of the workspace are clean before and after the fixes. |
| equivalence | no defect in the wrappers. The suite itself flaked: its step runner recorded `errno` on a fresh thread, which on this toolchain can start with `EAGAIN` (std's thread-start lock), failing ~1 run in 5 — 1 report: `misc/equiv-runners-read-errno-of-fresh-thread` (standalone reproducer; runner zeroes `errno` first). Noted, no test: a `set` message of `c_int::MAX` bytes or more cannot be formatted by C (`vsnprintf` fails) and leaves the buffer out of memory with the previous error in place; documented on `set`, `set_str` has no such limit. |
| internal | no defect. `runtime_pinned`'s fast path never touches `errno`; its slow path restores it on every thread. Added an inline test that, when libgit2 cannot be initialised (refusing allocator in a child process), every setter is a no-op, `set_str` fails with `MessageNotStored`, `clear` leaves `errno` alone and the refused pin is final. |
| conventions | none; `cargo clippy --workspace --all-targets` clean (after dropping the `.into()` calls the signature change made useless in `tests/{ub_safe,equiv}/errors.rs`), rustdoc of `libgit2` builds with `-D warnings`, new code is rustfmt-clean. |
| misc | see equivalence: the flaky runner. `tests/equiv/errors.rs` had the same runner defect, fixed by review batch 1 (`bf39b60f0`) concurrently. |
| coverage | C (`crustify/builds/coverage`, gcov): `git_error_clear`, `git_error_set` / `git_error_vset`, `git_error_set_str`, `git_error_set_oom` and `threadstate_get` reach every line and branch reachable through the public API. Unreachable: `git_str_init(.., 0)` failing (never allocates), the NULL-threadstate checks in `set_error` / `set_error_from_buffer` (callers hold one), `set_error`'s non-NULL string branch (only `git_error_restore`, internal), and `git_error_set_str`'s `GIT_ASSERT_ARG(string)` failure (NULL, which `&CStr` cannot express). Rust (llvm-cov): the five "libgit2 cannot be initialised" branches were uncovered and are now exercised by the new inline test; the remaining uncovered lines are the child-process assertion message in the test fixture. |
