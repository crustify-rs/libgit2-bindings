# Review: libgit2 / util / wave 0 / batch 0 (`git_allocator`, `git_error`)

Reviewed commit `1508d8ac2` (wave base; the items landed in `c647f7f01`, with
`git_error.klass` promoted to `ErrorClass` in `cb97c64a8` and `last()` added in
`dd95a582a`): `Allocator` / `AllocatorRef` / `AllocatorMut` and the `Alloc` trait in
`crustify/rust/libgit2/libgit2/util/sys/alloc.rs`; `Error` / `ErrorRef` / `ErrorBuf`
in `crustify/rust/libgit2/libgit2/util/errors.rs`.

| step | outcome |
|---|---|
| lifecycle discovery | complete. `git_allocator`: a plain vtable value; `git_allocator_setup` (`GIT_OPT_SET_ALLOCATOR`) `memcpy`s it, so it owns nothing and no owner is needed; the header's init routines are hidden (`git_stdalloc_init_allocator`, confirmed absent from `libgit2.so`'s dynamic symbols) or undefined (`git_win32_crtdbg_init_allocator`). `git_error`: published only by `const` pointer from `git_error_last`; `git_error_save` / `git_error_free` / `git_error_restore` are hidden (confirmed), so the owned form is the Rust copy `ErrorBuf`. No missing representation. |
| wavefront findings | verified against `errors.c`, `alloc.c`, `stdalloc.c`: field verdicts (static, nullable function pointers; `message` borrowed from the thread's `git_str` or a static literal, never NULL when published) and lifecycle roles are correct. No report. |
| safe boundary | no public `unsafe fn` in the workset; the `unsafe` items are the `Alloc` trait and the member types `MallocFn` / `ReallocFn` / `FreeFn`, which are C function pointers and must stay so. Their contracts were ambiguous for a zero-byte resize, and following them to the letter on the allocator the docs recommend double-frees — 1 report: `unsafe/alloc-realloc-contract-zero-size-resize` (ASan reproducer; fixed in the contracts, with regression tests). `ErrorRef`'s layout type cannot be forged by safe code (`define_ctype!` fields are private; `from_ptr` is `pub(crate)`), so its "live until the next libgit2 call" invariant is the crate's to keep, and `last()` keeps it. `crustify scan-unsafe --name git_allocator git_error`: every unsafe block documented, no raw-pointer or void-pointer smell; the only raw dereferences are the `addr_of!` field projections inside the handle impls. |
| UB | no candidate survived. Plain, ASan/UBSan (with LSan), TSan, BSan and Miri runs are clean on the reviewed tree and after the fixes. Reviewed by hand: `Send` / `Sync` on the allocator value and both handles (three code addresses, writes only through the exclusive handle); the trampolines' NULL handling and the `file` borrow; the thread-error `message` aliasing (`str.c`'s out-of-memory path frees the buffer `error.message` aliases, but redirects `last` to the static OOM error, so the dangling field is never published, and `last()` copies before any further call); the pre-init TLS hazard (pinned). |
| equivalence | no defect. Added a zero-byte request (`git_odb_backend_data_alloc(_, 0)`) to the traced C-vs-Rust allocator workload. |
| internal | no defect. Added `unit_tests::zero_byte_requests_are_allocations` (Miri) and `unit_tests::panic_in_the_implementation_aborts` (the documented abort of a panicking `Alloc`, in a child process). |
| conventions | none; the edited files are rustfmt-clean and `cargo doc -p libgit2` builds with `-D warnings`. |
| misc | the `last()` equivalence harness compared a fresh thread's start-up `errno`, which is not always 0, so `last_reads_each_threads_own_error` failed 3 of 15 runs — 1 report: `misc/equiv-last-errno-fresh-thread-flake` (fixed, 0 of 40 after; the batch 1 and batch 2 reviews found and fixed the same flake concurrently and landed first, so the wave's version was taken on rebase). |
| coverage | C: `git_error_last` 100% lines and branches; `git_allocator_setup` and `git_allocator_global_init` both branches; `stdalloc.c` 100%. Uncovered in `errors.c` are hidden routines (`git_error_save` / `restore` / `free`), other batches' symbols (`git_error_exists`, `git_error_system_*`), `git_error_global_shutdown` (a final shutdown, which the pinned runtime prevents) and `threadstate_get`'s `git_str_init(…, 0)` failure (unreachable: a zero initial size allocates nothing). Rust: both home files fully covered outside unit-test stubs that exist only to be compared by address; the new abort test's child cannot flush its profile (it aborts), as recorded before. |
