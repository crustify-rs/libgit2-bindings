# `TryFrom<c_int>` for `ErrorCode` / `ErrorClass` reports a bare `c_int` as its error

- **items**: `git_error_code` (`ErrorCode`), `git_error_t` (`ErrorClass`),
  `crustify/rust/libgit2/libgit2/util/errors.rs`
- **affected**: `impl TryFrom<c_int> for ErrorCode` and `for ErrorClass`
  (`type Error = c_int`), generated by the `c_enum!` macro
- **affected commit**: `cb97c64a8` (wave 0 batch 1)
- **class**: misc — API ergonomics; the conversion itself is correct and sound

## Finding

Both enums convert from the `int` libgit2 traffics in through `from_raw` (an
`Option`) and `TryFrom<c_int>`. The `TryFrom` impl handed the unrecognised value back
as its error type:

```rust
impl TryFrom<c_int> for $name {
    type Error = c_int;
    fn try_from(raw: c_int) -> Result<Self, c_int> { Self::from_raw(raw).ok_or(raw) }
}
```

A `c_int` is not an error type: it implements neither `Display` with a message nor
`std::error::Error`, so the idiomatic use of a `TryFrom` — `ErrorCode::try_from(rc)?`
in a function returning `Result<_, Box<dyn Error>>` — does not compile, and the value
cannot be attached to an error chain or logged as an error. It also made the `Err`
indistinguishable from any other `i32` in the caller's `Result`s. `from_raw` is the
primary path and was unaffected; this only concerned what the `TryFrom` idiom gives.

## Fix

`c_enum!` now also declares the error newtype for each enum, and uses it as
`TryFrom::Error`:

- `UnnamedErrorCode` — "a return code that this version of libgit2's header does not
  name: a callback's own result handed back, or a code of a later header";
- `UnnamedErrorClass` — "an error class that this version of libgit2's header does
  not name, which user code can set through `git_error_set_str`".

Each is `Copy`, `Debug`, `Eq`, `Hash`, keeps the value behind `raw()`, displays as
`libgit2 error code -2 is not named by git2/errors.h` (resp. `error class`), and
implements `std::error::Error`; being a plain `i32` it is `Send + Sync`, so it boxes
into `Box<dyn Error + Send + Sync>`. Both carry the `Handwritten` anchor.

Regression evidence: `unit_tests::unnamed_values_are_errors` (value, `Display`,
`Debug`, boxing, crossing a thread), and the existing rejection tests
(`unnamed_codes_are_rejected`, `unnamed_classes_are_rejected`, the equivalence
probes in `tests/equiv/errors.rs` and the UB probes in `tests/ub_safe/errors.rs`)
now match the newtype.
