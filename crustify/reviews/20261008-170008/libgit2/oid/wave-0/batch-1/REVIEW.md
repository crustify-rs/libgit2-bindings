# Review: libgit2 / oid / wave 0 / batch 1 (`git_oid_t`)

Reviewed commit `fc216e522` (wave base; `OidType` from `736863259`, wave 0 batch 1:
a fieldless `#[repr(u32)]` `#[non_exhaustive]` enum over the bindgen `git_oid_t`
constants in `crustify/rust/libgit2/libgit2/oid/oid.rs`, converted from a raw value
only through `from_raw` / `TryFrom` (`UnnamedOidType` for the rest) and back through
`raw()` / `From`, with `size` / `hex_size` from the `GIT_OID_*_SIZE` constants and
`Default` = `GIT_OID_DEFAULT`).

| step | outcome |
|---|---|
| lifecycle discovery | nothing to discover: a plain C enum with no storage, pointer or lifecycle routine (`wavefront query types --name git_oid_t --lifecycle-ops` is empty); libgit2 passes and returns it by value and `git_oid.type` stores it narrowed to a byte. No missing representation. |
| wavefront findings | one defect, `wavefront/options-zero-is-not-always-default`: the note said `0` means `GIT_OID_DEFAULT` in *every* options struct, but `git_diff_options` reads `0` as the repository's type and rejects a mismatch (`diff_generate.c:502`); it also missed that public routines *return* the unnamed `0` (`git_repository_oid_type(NULL)`, `git_remote_oid_type` on failure) and that `git_repository_init_ext` accepts an unnamed `oid_type` without validation and then fails to open the repository it wrote (`objectformat = unknown`). Resubmitted with per-site semantics and the asserting sites. |
| safe boundary | the workset's public API holds no `unsafe` and no raw pointer (`crustify scan-unsafe --name git_oid_t`: no sites); an `as` cast into the enum is rejected by the compiler (`ub_safe/compile_fail/oid_type_from_int_cast.rs`). Nothing to fix. |
| UB | none possible from the surface (no unsafe, no pointers, `Option<OidType>` keeps a niche no variant uses) and none found: plain, ASan/UBSan (with LSan), TSan, BSan (`equiv` + `ub_safe` oid suites, `--test-threads=1`) and Miri (Rust-only tests) are clean on the wave base and after the changes. No public unsafe API, so no `ub_unsafe` suite. |
| equivalence | no defect: every variant carries its C constant, `from_raw` names exactly the values `git_oid_from_raw` / `_from_prefix` / `_from_string` accept over a probe range, byte and digit counts match, `Default` is the `GIT_OID_DEFAULT` shim. Coverage gap filled: no test reached the C path that *returns* a `git_oid_t` — `tests/equiv/oid.rs::repository_oid_types_follow_the_rust_type` now creates a bare repository per option value (`0`, SHA1, SHA256), predicts `git_repository_oid_type` from `OidType::from_raw(raw).unwrap_or_default()`, checks what `git_oid_type_name` records in the config, reopens through `git_oid_type_fromstr` (`sha256`, an unknown `sha512` → `GIT_EINVALID`, a hand-written `sha1`), checks `git_repository_oid_type(NULL)` is a value `from_raw` refuses, and records the C-only `init_ext` quirk for an unnamed value. `git_repository_init_ext`, `git_repository_init_options_init`, `git_repository_oid_type` and the init options struct/flags/version were allowlisted in `libgit2-sys` for it. |
| internal | no defect: `from_raw` / `raw` / `TryFrom` / `From` / `Display` are covered line by line (`unit_tests`, `ub_safe`, `equiv`). |
| conventions | none: anchors (`Wraps: git_oid_t` + `Handwritten`) present, naming idiomatic, new code `rustfmt`-clean, `cargo doc -p libgit2 -D warnings` and `cargo clippy --workspace --all-targets` clean. |
| misc | 1 report, fixed: `misc/docs-overgeneralise-zero-as-default` — the module, `OidType`, `Default` and `UnnamedOidType` docs repeated the wavefront over-generalisation ("a zeroed `oid_type` means the default type"); they now name the repository-type exception and the routines that return `0`. |
| coverage | Rust: every executable line of `OidType`, its conversions and `UnnamedOidType` is covered (`cargo llvm-cov`, `coverage` variant). C (`src/libgit2/oid.h` inline helpers, gcov of the `coverage` build with a private `GCOV_PREFIX`): `git_oid_size` / `git_oid_hexsize` all three arms from `oid.c`; `git_oid_type_fromstr` all three returns and `git_repository_oid_type` both arms from `repository.c` (new); `git_oid_type_name` SHA256 and `unknown` arms (new). Unreachable from this workset: `git_oid_type_name`'s `sha1` arm (only `git_repository__set_objectformat`, an internal clone-time routine, names the default; `init_ext` skips it), `git_oid_type_fromstrn` (packfile / transport parsing) and `git_oid_algorithm` (hashing) — they belong to the repository, transport and odb sub-campaigns. |
