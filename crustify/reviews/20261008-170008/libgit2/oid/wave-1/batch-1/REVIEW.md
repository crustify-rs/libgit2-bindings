# Review: libgit2 / oid / wave 1 / batch 1 (the `git2/oid.h` symbols)

Reviewed commit `8cb33ad6b` (wave base; the items landed in `ed8e139b2`, wave 1 batch
1, with the wave 0 review's fixes on top of them): the 18 `oid.c` symbols wrapped in
`crustify/rust/libgit2/libgit2/oid/oid.rs` — the constructors `Oid::from_string` /
`from_prefix` / `from_raw` (`git_oid_from_*`), the copies `OidRef::to_oid` /
`OidMut::copy_from` (`git_oid_cpy`), the comparisons `Ord` / `PartialEq` /
`OidRef::eq_prefix` / `is_zero` / `cmp_hex` / `eq_hex` (`git_oid_cmp`, `_equal`,
`_ncmp`, `_is_zero`, `_strcmp`, `_streq`), the formatters `OidRef::format` /
`format_prefix` / `format_path` / `format_cstr` / `to_hex_string` (`git_oid_fmt`,
`_nfmt`, `_pathfmt`, `_tostr`, `_tostr_s`), and the shortener's `OidShortener::new` /
`OidShortenerMut::add` / `OidShortenerFree` (`git_oid_shorten_new` / `_add` / `_free`).
The types they sit on (`git_oid`, `git_oid_shorten`, `git_oid_t`) were reviewed in
wave 0.

| step | outcome |
|---|---|
| lifecycle discovery | a symbol-only workset; the lifecycle routines in it (`git_oid_from_*` init constructors, `git_oid_cpy` cloner, `git_oid_shorten_new` / `_free`) are the ones the wave 0 type review verified complete. Nothing missed, no report. |
| wavefront findings | every record verified against `oid.c` / `oid.h` / `errors.c`: the read bounds (`from_string` reads `str[hexsize]` only once the first `hexsize` are hex; `from_raw` reads exactly `git_oid_size(type)` bytes with no length; `strcmp` stops at the oid's size and the NUL; `ncmp` caps `len` at 64 digits), the write bounds of the five formatters (`nfmt` zero-fills past the hex size; `tostr` writes `min(n - 1, hexsize)` digits plus a NUL, `""` for `n == 0`, only a NUL for an unknown type), `tostr_s`'s unwritten thread string, `shorten_add`'s retained tails and 40-digit read bound, `cpy`'s non-overlap, and the lifecycle roles. All correct; no report. |
| safe boundary | no public `unsafe fn` and no public raw pointer in the workset: every argument is a handle, slice, `&CStr`, `&str` or `OidType`; the ffibox seams (`as_ptr` / `as_mut_ptr` / `from_ptr`) are `pub(crate)`. The three C contracts no type can carry are pre-checked before the call (`from_raw`'s length, `shorten_new`'s `int` round trip, `add`'s 40 hex digits) and the two unknown-type hazards (`tostr_s`, `tostr`) are refused or mapped to an error. `crustify scan-unsafe --name <the 18>`: no raw-pointer, deref or reference sites; every unsafe block documented. No report. |
| UB | none. Hand-checked every C read and write against what each wrapper passes (above), the shortener's trie walk (tails at depth ≤ 39 only, the depth-40 one-past tail never dereferenced, duplicates and 39-digit shared prefixes included), and the one abort path (`add` after a lost trie: errors.c sets the static OOM error whenever the thread has state, so "OID set full" in `last()` always means an intact trie). A seeded differential probe (200,000 random oid pairs, hex strings, prefix lengths and buffer sizes through every comparison, formatter and parser) agreed with C in the plain build and ran clean under ASan/UBSan. Plain, ASan/UBSan (LSan on), TSan, BSan and Miri suites are clean before and after the change. No public unsafe API, so no `ub_unsafe` suite. |
| equivalence | no defect. Regression evidence added to `tests/equiv/oid.rs`: `formatters_match_c` now sweeps every `nfmt` / `tostr` buffer length 0..=70 (every odd digit count and NUL position) instead of eleven, and `seeded_random_inputs_match_c` runs 400 xorshift-seeded rounds of comparisons (`cmp`, `equal`, `ncmp` with random and near-`usize::MAX` lengths, `is_zero`, `strcmp` / `streq` against random-length, mixed-case, occasionally bad or non-ASCII hex), formatters (random buffer sizes, the thread string included) and parsers (`from_prefix` and `from_string` on the same text) step by step against C on fresh threads. |
| internal | 1 report, fixed: `internal/format-cstr-empty-buffer-told-by-address` — `format_cstr` recognised the `n == 0` case (C returns its static `""`) by comparing the returned pointer with the slice's address; an empty slice's address is arbitrary, and a sound zero-length slice placed at that static string made the wrapper look for a NUL in zero bytes and panic (reproducer in the report directory). It now decides by `out.is_empty()`, `debug_assert`s the pointer otherwise; regression `unit_tests::format_cstr_tells_an_empty_buffer_by_its_length` fails on the old logic. |
| conventions | none: one filled anchor per item (`git_oid_cpy`'s two are the intended owning and in-place forms), naming idiomatic, methods on the handles they read or write, the new code `rustfmt`-clean (checked on scratch copies; the crate is not `cargo fmt`-clean), `cargo clippy --workspace --all-targets` and `cargo doc -p libgit2 -D warnings` clean. |
| misc | nothing further. |
