# Review: libgit2 / oid / wave 1 / batch 0 (`git_oidarray`)

Reviewed commit `8cb33ad6b` (wave base; the item landed in `b70e52aae`, wave 1 batch
0, and wave 2 batch 0 recorded that `git_oidarray_dispose` was already emitted with
it): `OidArray` / `OidArrayRef` / `OidArrayMut`, the owner `OidArrayVal =
CVal<OidArray, OidArrayDispose>` and the `OidArrayDispose` policy over `git_oidarray`,
in `crustify/rust/libgit2/libgit2/oid/oidarray.rs`, with ids moved in and out as
`OdbDataVec<Oid>`.

| step | outcome |
|---|---|
| lifecycle discovery | complete. C publishes one lifecycle routine, the disposer `git_oidarray_dispose` (`OidArrayDispose`); the library never allocates, clones or constructs the struct (header: "the library will never allocate that object directly"), the deprecated alias `git_oidarray_free` is hidden under `DEPRECATE_HARD`, and the `oidarray.c` helpers (`__from_array`, `__to_array` — which nothing calls —, `__reverse`, `__add`, `__remove`) are internal. Rust supplies the constructors (`new`, `from_ids`, `from_slice`) and the copy (`to_oid_array`) the C side lacks. No report. |
| wavefront findings | the `ids` field record (owned, nullable, by-value array in libgit2's allocator, NULL for every empty result) and `git_oidarray_dispose`'s record (a disposer; borrowed, non-NULL argument; fields left dangling) were verified against `oidarray.c`, `merge.c` (`git_merge_bases` / `_many`, `compute_base`, `oidarray_contains`), `smart_protocol.c`, `repository.c`, `fetch.c` and `local.c`, and are correct. The type note's claim that disposing an empty array before `git_libgit2_init` is "harmless" holds on one thread only — 1 report: `wavefront/empty-dispose-pre-init-note-incomplete` (note resubmitted). |
| safe boundary | no public `unsafe fn` in the workset: the handle seams are `pub(crate)`, the policy's `c_dispose` is ffibox's `CDispose` contract, and no safe path forges a handle or a populated bare `OidArray` (constructors return the owner; `into_inner` only leaks, as `mem::forget` does). `Send` / `Sync` on the value and both handles re-derived: 33-byte plain elements behind an exclusively owned pointer, writes only through `OidArrayMut`, `&OidArrayMut` reaching getters only. `crustify scan-unsafe --name git_oidarray git_oidarray_dispose`: every unsafe block documented, no raw dereference or field projection outside the impls; the one raw-pointer site is the FFI call in the hand-written policy. No report. |
| UB | 1 true defect: dropping an *empty* `OidArrayVal` called `git_oidarray_dispose` → `git__free(NULL)`, an unsynchronised read of `git__allocator.gfree`, which the process's first `git_libgit2_init` on another thread writes; nothing orders an empty array after that initialisation, since nothing allocated for it (every non-empty array's allocation pinned the runtime first). Found by TSan in the batch's own `views_stay_in_bounds`; proved with a `#![forbid(unsafe_code)]` two-thread reproducer — report `ub_safe/empty-array-dispose-races-first-init`. Fixed by a hand-written `OidArrayDispose` that skips C for a NULL `ids`; regression `tests/ub_safe/oidarray.rs::empty_array_drops_do_not_race_the_first_init` (TSan, isolated child; fails with the fix reverted) and `unit_tests::null_buffer_is_empty_and_disposes_without_c` (Miri proves the empty drop makes no foreign call). After the fix: plain, ASan/UBSan (with LSan), TSan, BSan and Miri are clean on every oidarray suite. Reviewed by hand with no further candidate: the `ids` / `ids_mut` run bounds (`count` against the invariant, NULL never a run base), `to_oid_array`'s non-overlapping copy including the empty case, `set_ids`' release-then-store order, `take_ids` on truncated buffers (whole allocation released, size ignored by `git__free`), `truncate` only lowering `count`, and the thread-safety claims. |
| equivalence | no defect: the step-by-step comparisons of libgit2-produced (`git_merge_bases`) and hand-built arrays — reads, in-place reversal, lowered `count`, replacement, move-out, copy, dispose — hold, with allocator events matched. The documented `free(NULL)` divergence now also covers the dispose of an empty array (the only observer would be a custom `gfree` counting NULL calls); the harness's tracing free already ignored NULL. |
| internal | 1 report: `internal/len-disagrees-with-ids-on-null-buffer` — on an invariant-breaking `{ NULL, count > 0 }` struct (reachable only through the crate-internal `from_ptr`) every accessor read the array as empty except `len()`, which returned `count`, and the batch's own test asserted the mismatch. `len()` now returns 0 without a buffer; in-contract arrays are unchanged. |
| conventions | none; the three edited files are rustfmt-clean, clippy-clean (`--workspace --all-targets`) and `cargo doc -p libgit2` builds without warnings. The policy carries the `Handwritten` anchor it now needs. |
| misc | none. |
| coverage | C (`oidarray.c`, coverage variant, this crate's suites): `git_oidarray_dispose` 100% of lines (no branches), `git_oidarray__from_array` covered through `git_merge_bases` (now also filling an `OidArrayVal` in place, `unit_tests::c_fills_an_owner_in_place`, the wrapper's documented primary use, which no test exercised before). The remaining `oidarray.c` lines are hidden helpers no public `git_oidarray` API reaches: `__to_array` has no caller at all, `__reverse` runs only inside `compute_base` (a recursive `git_merge_commits`), `__add` / `__remove` only in the smart transport's shallow negotiation — left to the merge and transport batches. Rust (`oidarray.rs`): 384 of 385 instrumented lines (was 309 of 310); the uncovered line is the child-failure message of the unit-test fixture. Added `tests/ub_safe/oidarray.rs::buffers_move_between_arrays_and_owners` (ids moved between live arrays, cloned runs, `into_inner` / `CVal::new` round trip, `Debug` of a populated array). |
