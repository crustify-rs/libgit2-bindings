| step | outcome |
|---|---|
| lifecycle discovery | complete, no gap. Each type is a caller-built value libgit2 neither allocates nor frees: its only lifecycle routine is the `*_options_init` template copy (the `GIT_*_OPTIONS_INIT` macros spell the same template), which each `new()` wraps; the deprecated `git_repository_init_init_options` / `git_worktree_add_init_options` aliases are outside the campaign's `DEPRECATE_HARD` build. No release, dispose or clone routine exists in the C (`InitOptions` and `NewOptions` are `Copy`; `AddOptions` deliberately not, as its embedded checkout options carry payload seams). Verified by reading `git_repository_init_ext`, `git_repository_new_ext` and `git_worktree_add`, the only consumers: each reads the struct for the call (`init_ext` also ORs its internal bits into `flags`, which the wrapper models by taking `InitOptionsMut`), and none keeps or frees a string or the reference. |
| wavefront findings | no defect. The three records (field notes, `_comment_agent`) were checked against the C and hold: the five strings and the reference borrowed for the call only, `init_ext`'s writes to `flags`, `new_ext`'s `GIT_ASSERT_ARG(git_oid_type_is_valid)`, `git_worktree_add`'s memcpy / `git_reference_dup` / by-value checkout options. Two records were extended with facts this review measured (below): `git_worktree_add_options` (what a failing checkout leaves on disk) and `git_repository_init_options` (an invalid template path, and where the `initial_head` / `template_path` defaults are read from). |
| safe boundary | nothing to fix. The workset adds no public `unsafe fn` and hands out no raw pointer: `as_ptr` / `as_mut_ptr` are `pub(crate)`, the strings come back as `Option<&'o CStr>`, the reference as `Option<ReferenceRef<'o, 'o>>` (attached only, so `git_reference_dup`'s `db` and `git_branch_is_checked_out`'s `db->repo` are live), the embedded checkout options as `CheckoutOptionsRef` / `CheckoutOptionsMut` projected in place. `crustify scan-unsafe` (unseeded, whole workspace) lists no smell site in the three wrappers' line ranges; the sites it lists in their home files belong to symbol-route items (`set_refdb`, the mergehead and fetchhead trampolines). Variance and thread-safety claims re-derived: `InitOptions<'o>` / `AddOptions<'o>` covariant in `'o` and `Copy` / move-only, the `Mut` handles invariant through `PhantomData<&'a mut _>`, `CBorrowedPtr` (`NonNull`) keeping every handle `!Send + !Sync` unless proven (`InitOptions` and `NewOptions` are: integers and `&'o CStr`s; `AddOptions` is not: its reference reaches a `!Sync` repository). All twelve `compile_fail` doctests of the three types fail with the code they name under nightly rustdoc. |
| UB | no candidate survived. Checked by hand: the template-copy constructors' `MaybeUninit` promotion (a 0 return means the whole struct was written; with its own version `git_error__check_version` sets no error, so `new()` needs no pinned runtime — the `*_needs_no_initialised_libgit2` children prove it); every getter reading through `addr_of!` on the shared handle's pointer and every setter writing plain data through the exclusive one; `reference()` rebuilding a `ReferenceRef<'o, 'o>` from a pointer only `set_reference` stores; the checkout projections' `from_ptr` contracts against `AddOptionsRef`'s `'a` borrow and `AddOptionsMut`'s exclusivity; `git_worktree_add` never writing through `opts` (a memcpy, then `coopts`, a second copy). Instruments on the whole workspace, on the reviewed tree and after the changes: plain, ASan/UBSan (with LSan), TSan (`-Zbuild-std`), BSan and Miri (Rust-only tests) are clean. No public unsafe API, so no `ub_unsafe` change. |
| equivalence | no defect; two gaps filled. Both `new()`s match `*_options_init` field by field, and the two step-by-step sequences (`equiv/repository.rs::init_options`, 16 inits; `equiv/worktree.rs::add_options`, 11 adds) compare returns, errors, the options after the call and the trees created. Added: (1) `init_options::defaults_read_the_global_configuration_as_c`, a child with `$HOME` set, proving `initial_head` / `template_path` left `None` read `init.defaultbranch` / `init.templatedir` as the C options do, that an explicit value overrides them alike, and that a reinitialisation keeps `HEAD`; (2) step `long-tpl`: a template path with an over-long component is `GIT_EINVALIDSPEC` (`GIT_ERROR_OS`, "invalid path for filesystem") after the repository directory exists, where a missing directory (or a file) falls back to the built-in template silently; (3) steps `theta`: a checkout failing through the embedded checkout options (a `target_directory` that is a file: `GIT_EEXISTS`) leaves a lookup-able worktree whose `HEAD` holds the branch checked out, so the corrected retry is refused as "already checked out" (`-1`). The C hazards in (2) and (3) are now on the wavefront records for the `init_ext` / `worktree_add` symbol batches. |
| internal | no defect. The private surface is three `as_ptr` / `as_mut_ptr` seams, the `PhantomData` markers and the layout asserts; the inline `unit_tests` (`repository.rs::init_options`, `worktree.rs::add_options`, and `sys/repository.rs`'s own) cover them line by line, and Miri runs the Rust-only ones, including the C-stored values the getters must read (`getters_read_what_c_may_store`, `any_nonzero_c_boolean_reads_true`) and the in-place projection of the embedded checkout options. |
