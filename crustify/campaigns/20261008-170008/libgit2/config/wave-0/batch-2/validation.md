# Config scalar parsers — wrap batch 2

## Analysis and boundary

Route verified: three exported functions (`symbol`), objective `wrap`. The C
implementations in `src/libgit2/config.c:1409–1487` are unchanged. Definitions,
public declarations, callers, and the dependency closure were inspected using
Wavefront and source; ownership was submitted with `query symbols --update`.

* `out` is a nonnull, exclusively writable scalar slot, written only on success.
  It is neither retained nor freed. Rust supplies an initialized local and returns
  only the successful scalar, never exposing an output pointer.
* `value` is a nullable, read-only, NUL-terminated byte string, borrowed only for
  the call (including error formatting). No retention, ownership transfer, clone,
  or release occurs. Callers release config entries, strings and configs after
  parsing. Rust uses `Option<&CStr>` and returns an independent scalar/error copy.
* NULL means true for bool and failure for integers; empty means false for bool
  and failure for integers. Numeric bool values must fit int32, not merely int64.
* `git__parse_bool`, `git__strntol64`, checked multiplication and error reporting
  stay C-owned. The wrappers pin the existing runtime before every FFI call,
  including the paths that set an error. Runtime failure returns the existing
  owned initialization error without entering C.
* `git_config_parse_int64` fails on text following a valid suffix without setting
  a new error. Both this stale-error behavior and success preserving error state
  are documented and compared to C. No new public unsafe API is introduced.

The sys function allowlist adds exactly the three missing bindings; bindgen was
regenerated by the sys build and its tests passed. No shim or compiled C changed.
Wavefront canonicalized the ownership store's ordering; semantic comparison with
HEAD found only the three new symbol records and no changes to prior records.

## Validation

* `cargo check --workspace`, `cargo clippy --workspace`, and additionally
  `cargo clippy --workspace --tests`: passed.
* `cargo test --workspace`: passed (584 unit, 366 equiv, 620 ub_safe, 91
  ub_unsafe, 42 sys layout, 219 doctests; one pre-existing ignored unit test).
* ASan/UBSan: config-filtered workspace tests passed, including nullable inputs,
  all byte values, bounded suffix lookahead, long inputs, every multiplication
  overflow stage, int32/int64 limits, input drops/reborrows, owned error copies,
  initialization failure, and concurrent first-use initialization.
* TSan: all four new parser integration tests passed together. The broader
  substring `config` run also selected the existing
  `types::configured_ignore_values_are_named` raw fixture. It raced an
  uninitialized raw repository allocation against `config::new_configs_match`'s
  raw `git_libgit2_init`, reporting `git_str_try_grow` versus
  `git_stdalloc_init_allocator` (exit 66). Neither side uses the new parsers.
  This unrelated fixture issue was not changed. The broader config tests then
  passed with `--test-threads=1`; the parser test still creates six simultaneous
  worker threads internally and passed both runs.
* BSan: only the exact names below were run, each separately under a 300-second
  timeout; all passed. These target foreign scalar writes and later Rust reads,
  non-retained input borrows/reborrows, and thread-local error ownership:
  `config::parsers::nullable_and_boundary_inputs`,
  `config::parsers::results_outlive_inputs_and_later_calls`,
  `config::parsers::first_parser_errors_race_to_init`, and
  `config::parsers::parse_sequences_match_c` (equiv binary).
* Miri: the three public-safe integration tests compiled and were explicitly
  ignored because Miri cannot call libgit2. This batch adds no Rust-side layout,
  pointer projection, adoption or initialization assumptions independently
  executable by Miri. No `ub_unsafe` suite is needed (no new unsafe API).
* `crustify scan-unsafe ... --json --sites unsafe_fns_pub_smell
  raw_ptr_pub_smell unsafe_fns_priv_smell raw_ptr_priv_smell
  ref_to_type_wrapper_smell`: no sites in config/config.rs; zero undocumented
  unsafe blocks in that TU. `git diff --check` passed.

## Coverage

The prepared C coverage build and Rust `cargo llvm-cov` were used. Each public
parser reached every Rust region (18/18 per function, aggregating unit and
integration instantiations), including the initialization-failure early return.

A separate single-test equivalence coverage run (no concurrent counter updates)
hit all 38 executable source lines in the three C functions and 30/31 reported
branches. The only uncovered source branch is the NULL alternative when reporting
a failed boolean parse: NULL succeeds immediately in `git__parse_bool`, so this
branch cannot be reached. Focused inputs added after the initial measurement hit
the first and second suffix-multiplication overflow paths, not just final overflow.
The prepared gcov tool reports block summaries of 88% for bool/int64 and 100%
for int32; all executable source lines and all reachable reported source branches
are covered. The equivalence test replays independently owned strings with both
empty and seeded initial errors, comparing results, unchanged failed C outputs,
error class/message bytes, and error-state transitions after every step.

Raw logs, scan JSON, Rust coverage JSON and C gcov output are retained under
`crustify/tmp/config-batch-2/` (ignored artifacts).
